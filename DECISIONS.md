## Shared gotchas (inherited across the demo family — verified)

Once-bitten-twice-shy log. These recur; check them before you re-discover them.

- **`CREATE OR REPLACE FUNCTION` revokes EXECUTE grants.** A reset that recreates a UC function drops the app SP's EXECUTE → re-grant after any function recreate, or the app 500s. (Prefer not recreating governed functions on every reseed.)
- **Genie space creation:** create the space **programmatically via the Databricks API** (`databricks api post /api/2.0/genie/spaces --json @file`; builder utility under `tools/`), never hand-built in the UI. SDK `create_space` / raw REST / CLI `create-space` have failed on `serialized_space` encoding — use the API builder. In-app query via the Conversation API + `execute_message_attachment_query` (sdk ≥ 0.133); grant the app SP `CAN_RUN`. Keep a space ≤ ~30 tables.
- **Databricks Apps serve stale HTML:** the static SPA shell has no `Cache-Control` by default, so a redeploy's new frontend/JS is masked by the browser cache. Add middleware forcing `Cache-Control: no-store` on `text/html` responses so redeploys show immediately.
- **Apps config:** `app.yaml` uses `valueFrom` (camelCase); OBO scopes are IAM-only; Apps listen on port 8000. App SP needs schema `USE/SELECT/EXECUTE/MODIFY`, warehouse `CAN_USE`, Genie `CAN_RUN`, reset-job `CAN_MANAGE_RUN`.
- **Serverless + files:** install openpyxl via `%pip`; write xlsx to `/tmp` then `shutil` copy; give pandas→Delta appends an explicit schema so ints don't land as the wrong type. No `cache()` on serverless.
- **`ai_parse_document` / `ai_query`:** run in the pipeline (jobs/DLT), not the app container. `ai_query` takes the endpoint name + prompt; bind the prompt, don't string-concatenate untrusted text. Prefer `responseFormat` / structured output where available so the dictionary-constrained JSON parses cleanly.
- **Bundle auth on macOS:** `databricks bundle deploy` may need an unsandboxed shell (keychain access) or it exits 45. DAB dev mode prefixes deployed names.
- **Self-contained SPA + inline scripts (the fragile trap):** a view that returns an HTML string containing an inline `<script>` creates three hazards, none caught by API/curl tests — only by loading it in a browser. (1) A literal `</script>` inside the JS string closes the outer `<script>` in the HTML parser → white screen; write `<\/script>`. (2) Scripts injected via `innerHTML` do NOT execute — `render()` must re-create them (`app.querySelectorAll('script').forEach(o=>{const s=document.createElement('script');s.textContent=o.textContent;o.replaceWith(s);})`). (3) Inside the inline script, inner template-literal backticks/`${` must be escaped (`` \` ``, `\${`) so the OUTER view template doesn't consume them — BUT a `${...}` meant to bake a view-scope value into the generated script must stay a REAL `${}` (outer interpolation).
